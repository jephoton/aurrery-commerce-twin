# 0007: Consistent authoritative ledger export and bounded readiness

**Status:** accepted offline implementation; live Turso and Render acceptance pending.

Render Free's ephemeral files cannot serve as payment authority. A backup must capture current primary approvals, execution claims and observations together. Turso's basic CLI export warns about stale snapshots, and independently reading tables can mix before/after states.

Take one checked libSQL primary write transaction over an existing canonical source, with no schema initialization, source row changes, sync or retry. Validate its full schema/integrity/FKs and reuse importer record validation. Read all canonical tables in their established order, reconstruct a private local SQLite file, apply the existing atomic snapshot/manifest checks and run the read-only importer validation. Preserve pilot order, sequences, all action/approval/execution/claim variants and hosted/cache/event state. Publish exclusively only after verification. Local SQLite backups use the supported read-only online backup API, including committed WAL pages, and keep legacy optional-table import compatibility. Restore remains explicit into an empty target with PayPal reconciliation before further execution; a restored approval never becomes a fresh authorization to replay.

Render health checks need a response within five seconds and run frequently. The request-only readiness route validates runtime settings and worker availability, then performs a small authoritative transaction/query without business/audit/quota rows or provider/PayPal calls. A global coalesced probe, two-second cache and 3.5-second response deadline bound demand. Early responses keep underlying probe ownership until settlement instead of spawning more work on every check. Runtime-only validation permits a first URL bootstrap before configuring the genuine webhook ID. Builds require no runtime credentials or ledger access.

Consequences: exports briefly serialize writers and require a private local destination; retained snapshots contain sensitive authority. Readiness checks database/configuration availability, not successful model inference, PayPal reachability, worker job execution or genuine webhook delivery. Live persistence, signed events and browser acceptance remain separate gates. See the [runbook](../runbooks/render-turso.md), [Turso export warning](https://docs.turso.tech/cli/db/export) and [Render health checks](https://render.com/docs/health-checks).
